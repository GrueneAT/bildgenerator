Strategy summary

Additive, low-coupling work on top of the merged z6qfk Barlow font infrastructure. The plan adds Vollkorn to the existing font machinery and re-introduces a tiny descriptive picker — it does not rewrite the text system.

  • Reuse, don't rebuild.

    FontFaceObserver preload, loadFont() re-render and centralized AppConstants.FONTS already exist; the work extends them for a second family.

  • Descriptive labels, never brand names.

    Users don't recognize "Vollkorn"/"Barlow"; both options are labelled by type and use ("Standardschrift", "Betonte Serifenschrift").

  • The preload family trap.

    preloadFonts() binds every entry to the single Barlow family — appending Vollkorn naively gives it a Barlow observer, so it never preloads and renders a serif fallback. Entries must carry a per-entry family.

03Decisions

Key decisions & options

Where the font choice lives

Chosen

A 2-option <select id="font-style-select"> in the Step-3 text section, next to the existing color/line-height selects. Reusing the removed id is safe — zero remaining references.

A separate "advanced options" panel — the text section is where users already pick text properties.

Vollkorn canvas weight

900 upright

Weight 900 upright matches Barlow's heavy default and the design-system font request (upright 400/900, no italic).

Weight 400 for a softer quote look — rejected for visual parity and readability at headline sizes.

Vollkorn italic — the DS doesn't load it; requesting it makes Fabric fall back.

Preload family binding

Load-bearing

Each PRELOAD_FONTS entry carries its own family and preloadFonts() uses it — otherwise Vollkorn gets a Barlow observer and never preloads.
